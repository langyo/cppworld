# 瓶子与漏水防护 · 数组库与再探原生数组

前面学了原生数组 ```int arr[10]```，也学了 ```vector```。但还有一种更贴近传统数组的选择——```array```。它把数组的"零开销"性能保留下来，同时堵上了原生数组最痛的几个漏洞。

------

原生数组有三个著名的漏水点。

**第一个是退化为指针。** 当你把数组传给函数时，它并不会把整个数组都送过去：

```cpp
void printArray(int arr[])          // arr 实际上是个 int*，不知道大小
{
    // sizeof(arr) → 4 或 8（指针大小），不是数组大小！
    // 你只能额外再传一个 size 进来
}
```

**第二个是没有越界检查。**

```cpp
int data[10];
data[15] = 42;                      // 编译通过，运行时可能炸、可能不炸但破坏了别的变量
```

**第三个是不能直接拷贝。**

```cpp
int src[5] = {1, 2, 3, 4, 5};
int dst[5];
// dst = src;                        //   编译错误——数组不能整体赋值
```

------

```array``` 就是来堵这些漏的。它在 ```<array>``` 头文件中，形式上写作 ```array<T, N>```：在栈上分配连续内存（和原生数组一模一样），却提供了 ```size()```、迭代器、```at()``` 等标准容器接口。

```cpp
#include <array>
#include <iostream>

int main()
{
    array<int, 5> arr = {1, 2, 3, 4, 5};

    cout << "大小: " << arr.size() << "\n";      // 5 —— 不会退化！
    cout << "arr[2] = " << arr[2] << "\n";       // 3
    cout << "arr.at(3) = " << arr.at(3) << "\n"; // 4 —— 带越界检查

    // 不会退化的函数传递
    for (int x : arr)                                  // 范围 for 可用
        cout << x << " ";
    cout << "\n";

    // 整体拷贝——原生数组做不到的事
    auto copy = arr;                                   // 底层所有元素自动复制
    copy[0] = 999;
    cout << "arr[0] = " << arr[0] << " (不受影响)\n";   // 1

    try
    {
        cout << arr.at(10) << "\n";    // 越界——抛 out_of_range
    }
    catch (const out_of_range& e)
    {
        cerr << "异常: " << e.what() << "\n";
    }
}
```

```array<int, 5>``` 和 ```array<int, 6>``` 是两种不同的类型——大小是类型的一部分。所以 ```array``` 不能像 ```vector``` 那样在运行期改变大小，但换来的是和原生数组完全相同的布局和性能。

------

来一个应用：用 ```array``` 管理 12 个月的天数，干净利落：

```cpp
#include <array>
#include <iostream>

int main()
{
    const array<int, 13> daysInMonth = { 0, 31, 28, 31, 30, 31, 30,
                                                31, 31, 30, 31, 30, 31 };
    // 下标 0 占位，让 1 月对下标 1

    int month;
    cout << "输入月份 (1-12): ";
    cin >> month;

    if (month < 1 || month > 12)
        cerr << "无效的月份\n";
    else
        cout << month << " 月有 " << daysInMonth.at(month) << " 天\n";
}
```

```at()``` 保证即使用户输入了 13，程序不会默默去读不存在的位置，而是干净地抛出异常。

------

把三种方案摆在一起比较：原生数组大小不可变、传给函数会退化、越界检查全无、内存分配在栈上，典型场景是与 C API 对接、嵌入式开发；```array``` 大小同样不可变，但传参不退化、有 ```at()``` 越界检查、也在栈上，适合"编译期就能确定大小 + 想要容器接口"的情况；```vector``` 大小可变、传参不退化、有 ```at()```，内存分配在堆上，覆盖几乎所有日常场景。

规律很简单：**能用 ```vector``` 的地方别用原生数组；如果大小是编译期常量且想要容器接口，用 ```array```；剩下只有和 C 库交互、嵌入式极端环境才回到原生数组。**
